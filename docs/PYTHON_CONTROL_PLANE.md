# Python control plane

## Verdict

Python does not make Claude more intelligent. V4.4 uses Python to make selected Claude Code work
more deterministic, policy-gated, structured, repeatable, and auditable.

The Python layer is the authoritative orchestration engine. It does not replace:

- the interactive Claude Code CLI;
- project `CLAUDE.md` and rules;
- specialized subagents;
- skills;
- hooks;
- Git branches, commits, or worktrees;
- Founder approval.

## Runtime architecture

```text
Founder / operator
      |
      +--> interactive Claude Code
      |       planning, steering, pair programming, checkpoints, visual judgment
      |
      +--> madclaude Python control plane
              |
              +--> fail-closed auth and billing preflight
              +--> repository / Git / approval / scope guards
              +--> native `claude -p` backend (default)
              |       saved subscription login
              |       structured JSON Schema output
              |       ephemeral PreToolUse policy
              |       strict empty MCP
              |       route-specific tools and subagents
              |
              +--> Agent SDK backend (optional, explicit API billing only)
              +--> Python-run verification
              +--> redacted SHA-256 evidence bundle
```

## Default backend: native `claude -p`

V4.4 defaults to:

```text
--backend cli
--billing-mode subscription
```

Python invokes the supported non-interactive Claude Code interface and preserves the user's saved
Claude subscription login. It does not require an API key.

Each run receives:

- the `claude -p` programmatic interface;
- a route-specific model and effort;
- a bounded turn count;
- JSON Schema structured output;
- explicit tool and disallowed-tool lists;
- project settings only;
- strict empty MCP configuration;
- an ephemeral `PreToolUse` hook generated by Python;
- a route-specific allowed-subagent registry;
- an explicit mutation scope when the route can write.

The ephemeral hook is important for exact-SHA review. A detached worktree may contain only the
reviewed commit, not the newly installed V4.4 files. The Python-generated hook still enforces policy
because it is supplied outside the target commit through `--settings` and removed after execution.

The project-level `.claude/hooks/hook-adapter.mjs` is a transport-only adapter into the same Python
policy package. It enforces baseline policy before tools and configuration changes, and blocks task
completion when a dirty tree lacks current manifested Python verification evidence. See
[Hooks and canonical artifacts](HOOKS_AND_ARTIFACTS.md).

## Optional backend: Claude Agent SDK

Install the optional SDK only for an explicitly API-billed integration:

```bash
./scripts/install-python-control-plane.sh --with-sdk
```

```powershell
.\scripts\install-python-control-plane.ps1 -WithSdk
```

The adapter is pinned to:

```text
claude-agent-sdk==0.2.131
```

It uses the Claude Code system-prompt preset, project settings, structured output, strict empty MCP,
file checkpointing, explicit tools, and an in-process `PreToolUse` policy hook. V4.4 refuses
`--backend sdk` in subscription mode. This is a package governance decision designed to keep the
user's ordinary subscription lane unambiguous; the native CLI is the supported default.

## Installation

The full repository installer copies transparent source to:

```text
.claude/control-plane/
```

Install the user-level wrapper without downloading any Python dependency:

```bash
./scripts/install-python-control-plane.sh
```

PowerShell:

```powershell
.\scripts\install-python-control-plane.ps1
```

The installer creates:

```text
~/.madclaude/
├── app/       transparent packaged source
└── venv/      isolated Python runtime

~/.local/bin/madclaude
```

The default installation performs no package download and does not need the Agent SDK. It never
creates or changes Claude credentials.

The full environment installer can install both the repository package and wrapper:

```bash
./scripts/install.sh /absolute/path/to/repository \
  --profile auto \
  --install-python-control-plane
```

Optional API SDK:

```bash
./scripts/install.sh /absolute/path/to/repository \
  --profile auto \
  --with-python-sdk
```

## Authentication and billing

First authenticate Claude Code through the subscription account:

```bash
claude auth login
claude auth status
madclaude auth-check --repo .
```

In subscription mode, an active `ANTHROPIC_API_KEY`, provider route, API-key helper, gateway, custom
base URL, or ambiguous auth state stops the run before Claude starts. A second model-entitlement gate
then blocks Fable on Pro or unproven Team/Enterprise seat classes unless the operator selects
`--model opus` / `--model sonnet` or explicitly supplies `--allow-usage-credits`. Max Fable routes are
allowed with a warning because remaining Fable allowance cannot be inspected. The acknowledgement
never enables credits. API mode requires:

```text
--billing-mode api
--allow-api-billing
--max-budget-usd <positive number>
```

See [Authentication and billing controls](AUTHENTICATION_AND_BILLING.md).

## Route registry

| Route | Model | Effort | Mutation | Subagents | Deterministic gate |
|---|---|---|---:|---|---|
| `plan` | Fable | high | No | Explorer, dependency mapper | Evidence-grounded structured plan |
| `build` | Sonnet | high | Yes | None | Clean tree, plan-bound Founder approval, scope, verification |
| `verify` | Opus | high | No | None | Python-executed direct commands |
| `tier2` | Fable | xhigh | No | None | Literal full SHAs, detached worktree, unchanged proof |
| `release-readiness` | Fable | xhigh | No | None | Exact-SHA readiness evidence only |
| `repo-audit` | Opus | high | No | Five read-only specialists | Structured repository audit |
| `security-audit` | Fable | high | No | Security reviewer, adversarial verifier | Adversarial structured findings |
| `ui-review` | Opus | high | No | UI reviewer, explorer | Truthful source review |
| `fix-until-green` | Sonnet | high | Yes | None | Bounded repair, scope, deterministic verification |

Only read-only routes may fan out. Mutation routes deliberately keep one accountable builder.
Subagents can use only the parent route's allowed repository tools; shell, web, skill, MCP, nested
subagent, secret-path, and mutation escapes are denied by the policy hook.

Model aliases resolve through the user's Claude Code account. Account availability is checked at
runtime; the package does not silently substitute a different judgment tier. Model entitlement is
checked separately from authentication for Python Fable/ambiguous-model routes.

```

```

## Governed build sequence

### 1. Produce a structured plan

```bash
madclaude plan \
  --repo . \
  "Implement the approved feature"
```

The evidence bundle contains the structured output and plan file. No repository mutation is allowed.

### 2. Generate a non-approved approval template

```bash
madclaude approval-template \
  "Implement the approved feature" \
  --plan-file /path/to/plan.json \
  --output /path/to/founder-approval.json
```

The template is deliberately not approved. Founder authorization must populate the exact approval
reference and approved fields.

### 3. Run the approved build

```bash
madclaude build \
  --repo . \
  --plan-file /path/to/plan.json \
  --approval-file /path/to/founder-approval.json \
  "Implement the approved feature"
```

The build gate requires:

- a clean repository;
- the exact goal;
- the exact plan SHA-256;
- explicit Founder authorization evidence;
- allowed mutation scopes;
- acceptance criteria;
- direct verification commands.

Python executes the approved commands after the builder returns. Builder prose cannot override a
failed command.

## Exact-SHA review

```bash
madclaude tier2 \
  --repo . \
  --base-sha <40-character-base-sha> \
  --head-sha <40-character-head-sha> \
  --verify "npm test" \
  "Independent Tier-2 review"
```

The route:

1. requires literal full SHAs;
2. proves ancestry;
3. captures changed files and a bounded diff;
4. rejects sensitive changed paths or credential-looking diff content;
5. creates a detached temporary worktree at the exact head;
6. runs deterministic verification there;
7. starts an edit-less reviewer with the ephemeral policy hook;
8. proves the worktree remained unchanged;
9. removes the worktree;
10. emits an exact-SHA evidence bundle.

A truncated diff, failed command, mutation, or later commit prevents the prior verdict from being
represented as current approval.

## Bounded repair

```bash
madclaude fix-until-green \
  --repo . \
  --allowed-scope src/auth \
  --allowed-scope tests/auth \
  --verify "python -m pytest tests/auth" \
  --max-rounds 3 \
  "Repair authentication tests without changing public behavior"
```

Each round runs verification first, fingerprints the failure and tree state, invokes one scoped
builder, proves content progress, enforces changed-file scope, and repeats. It stops on success,
repeated failure, no progress, invalid output, scope escape, policy violation, or the round limit.

## Verification command policy

Accepted commands are parsed into direct argument vectors:

```text
npm test
npm run build
python -m pytest tests/auth
git diff --check
```

The parser rejects shell control syntax, redirection, destructive operations, credentials, network
or deployment tools, package mutation, commits, pushes, merges, tags, releases, and other
authority-changing commands.

Claude never receives shell tools inside these routes. Python runs the reviewed verification command
after policy validation.

## Evidence

Every route writes under:

```text
.claude/evidence/python-control-plane/<route>/<run-id>/
```

A bundle may include:

- redacted auth preflight;
- request and route configuration;
- Git state;
- prompt;
- structured output;
- deterministic verification;
- changed-file evidence;
- exact-SHA target data;
- SHA-256 manifest.

Local evidence is not automatically a ratified governance record, merge authorization, deployment
authorization, production proof, or billing ledger entry.

## Exit codes

```text
0   route and controlled gate completed
3   preflight, configuration, repository, policy, backend, or runtime failure
10  route ran, but the controlled gate did not pass
130 interrupted
```

## Choose Python only when it adds control

Use ordinary Claude Code for interactive work where the Founder is steering each step. Use Python
when the workflow benefits materially from deterministic ordering, structured schemas, hard scope
gates, exact-SHA isolation, machine-executed verification, bounded loops, or reproducible evidence.
